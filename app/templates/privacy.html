What this server can and cannot see

Short version: it sees a sealed box, a counter and a clock. It does not see what is inside the box, who opened it, or where they came from.

The server can see

  • The random id of a link, e.g. /l/Ab3xQ9….
  • An encrypted blob (AES-256-GCM ciphertext), its 96-bit IV, and a salt if the link has a password.
  • How many opens are allowed, how many have happened, and when the link expires or activates.
  • Whether a note exists inside the blob — a single yes/no flag, not its text.
  • When a link was created, rounded to the hour.
  • The hash of the manage token, never the token.

The server cannot see

  • The destination URL or URLs. They are encrypted in your browser before anything is sent.
  • The note, the password, or the key. The key lives after the # in the share link, and browsers never send a fragment to a server.
  • Who opened a link: no IP address, no user agent, no referrer, no device fingerprint, no cookie, no per-click row.

What is logged

Nothing about a link open. The web server writes no access-log line for /l/*, /m/* or /api/links/*, and the application stores no click record of any kind. Rate limiting keeps a short-lived HMAC of the client address in process memory only; it is never written to disk and is gone when the process restarts.

Retention

  • A spent or expired link's ciphertext is overwritten immediately, not flagged.
  • The contentless row that remains answers 410 Gone and is deleted after seven days.
  • There is no archive of link content to retain.

Third parties

The page you open from a link (/l/…) loads no third-party script, no font, no analytics and no network bar — anything on that page could read the key. The rest of the site loads only the Kituwa network bar from hub.kituwa.com. There is no Google, no reCAPTCHA and no CDN.

Links created before 26 November 2026

Older links were made when this service stored destinations in plaintext. Their destinations were disclosed to the server at creation and cannot be un-disclosed; they keep working until they expire or are used up, and are then deleted. Their click history — addresses, devices, referrers — was deleted when the new model went live. Nothing new is recorded for them either.

Open source

The code that runs here is public at {{ repo_url }}. The verify page shows the exact commit and how to check that this server runs it.

What this does not protect against

If the server itself were compromised, it could serve modified JavaScript to the next visitor and read the key from that page. That is why the page is small, has no third-party code, ships with strict CSP and SRI, and why the release is signed and reproducible. It is also why the code is public: you do not have to trust the operator's description of it.
